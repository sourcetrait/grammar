# remote_engine_set.rs

`interface remote engine set` and `unset`, the remotes file's engine writes.

## fn NuSh::engine_set
The parameters become the change field for field, so a set changes what it
names alone. An interface flag takes a string or a list, never either, so the
known hosts arrive by two flags, `--known-hosts` for the keys and
`--known-hosts-file` for a file, each replacing the other's form and the two
together refused. A set that worked answers nothing (User); `get` or `list`
reads the entry.

## fn NuSh::write_engine
The change is held to its fields' checks before the file is touched, so a bad
value answers `remote::engine::invalid_params`; a file the edit can't read,
parse, or write answers `remote::file`. A change giving a jump holds the
entries as it would leave them to the jump's rules first, so a jump to no
engine, or one that would chain, answers `invalid_params` too, not the file's
kind. The write is the peer's locked edit, the one a channel's set takes. An
import writes through it too.

## fn NuSh::engine_unset
An alias the file lacks is refused before the write, and so is an engine
another entry jumps through, by that entry's alias, until its jump changes. A
live session stays, its work its own, until a close or the MCP's end; no new
call routes to it, the entry being gone.
