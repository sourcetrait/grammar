# bed.rs

The `bed` tool (User): one embedded engine command, `grmr`'s, by the interface
tool's rules and documentation, so a simple call, a peer's message among them,
needs no `execute` definition; `execute` stays available everywhere it was.

## const BED_PRETEXT
User's `include/human/mcp/bed.md`, verbatim by `include_str!`, his from its
copy (User).

## struct BedParams
`command` the embedded command, `subcommand` its subcommand, each the end
user's nu text, its command's word optional in the subcommand as `interface`'s
is in the interface tool's.

## fn bed_description
His pretext, then the `grmr` signatures the deny set leaves, as the interface's
description is its pretext and its commands' list.

## const BED_DESCRIPTION
The router's stub, which `bed_description` replaces on the router.

## fn bed
The nonce is minted first, over the tool's name and its parameters, so a
refusal carries one; the host is routed before anything else, and a `grmr`
command the deny set withholds is refused here, a `bed::invalid` row, before
the request leaves the MCP. Everything else is the engine's, the local one's or
a remote engine's grammar-ssh, which holds the command to the rules and runs it
as its own call.

## fn withheld
The `grmr` command a call names is the name its text opens with as whole words,
the command's word prepended as the parse prepends it, so `grmr get_config` is
never `grmr get_config_all`; the longest wins should one name ever lead
another.
