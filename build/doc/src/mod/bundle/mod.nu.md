# bundle/mod.nu

What grammar's release holds; `optzst` packs it into an OptZst.

## const SSH_CRATE
`grammar-ssh`, the MCP on a foreign host, ships in one tree with the MCP, built
from the same lockfile in the same invocation, so a grammar-ssh installed from a
release speaks the protocol of the MCP released with it.

## const CORE_PLUGINS
nushell's core plugins are pulled from crates.io as published, never
mirrored into the workspace: upstream's own `main` and its own lockfile
build each one, so the list of names is the one thing kept here.

## const SYSTEMD_USER_FILES
The runtime cleanup, a user tmpfiles rule and the one command that links it
(`build/sys/systemd/user/`), under `user/` since both are the user manager's:
the package carries them for a person to run once by hand, since an OptZst's
install links `bin/` and runs nothing of its own.

## const EQUIPS
The builtins the package carries for the host to install into a new namespace:
grammar's equip from this repository, gram's from its own repository through
`ext/gram`, a relative link to a clone beside this one, so the build names no
path outside the tree.

## def require_gram
gram's equip is the one source outside the tree, so it is checked first, with
the signer, and a missing clone stops the build in a second, naming the
requirement, rather than after the release compiles.

## def licenses
cargo-license's tally over the whole workspace, each license expression with
the crates under it, regenerated by every whole build: it follows the
dependencies as they move, and a build that moved them leaves the tally's
change in the tree to commit. It is the repository's record; the package
carries none.

## def compile
The MCP, grammar-ssh, and the workspace's plugin crates build in one cargo
invocation, so one lockfile resolves them all against the same nushell crates
and the plugins speak the engine's nu-plugin-protocol. `--locked` holds the
build to the lockfile as committed, so a release never resolves a dependency
its tests didn't build.

## def nushell
`cargo install --locked` builds nushell's own binary and its core plugins
from crates.io, each against its published lockfile. Their version is the
workspace's `nu-protocol`, read from our lock, so the shell the package
carries is the engine the MCP embeds and every core plugin speaks its
protocol. A target directory of their own, `nu/build` in cargo's, keeps their
builds incremental and apart from the workspace's.

A release's binaries carry no symbols, a crash being debugged on a debug build,
and the workspace's release profile strips its own. Each published crate's
manifest keeps its symbols, so a release install sets
`CARGO_PROFILE_RELEASE_STRIP`, which overrides a manifest's profile, and forces
the install: cargo's install record holds no strip setting, so an earlier
install at the root would otherwise stand. A forced install whose build is
fresh only copies it. A debug install keeps cargo's skip of a crate already
installed at that version.

A build with no network, a source package's on a distribution's builder,
names `sources`, a directory holding each crate's published source as
`<crate>-<version>/`, and each installs from there by `--path`, `--offline`,
still against its own published lock: the crates its lock reaches come from
the vendored sources cargo's configuration points it at. `--path` takes one
package an invocation, so each installs in its own.

## def target_dir
cargo's own answer, `cargo metadata`'s `target_directory`, which honors
`CARGO_TARGET_DIR` and cargo's config, so nushell's install, the tree, and the
package land where the build did. A `target/` assumed beside the manifest
would hand the package whatever an earlier build left there whenever the
environment names another, as the build container's does.

## def target
Rust's `target_os` and `target_arch` rather than `uname`: the names cargo built
for, the same when a cross build arrives. `_` becomes `-` because the file name
reserves it; x86_64 is the case that needs it. musl's os takes its libc,
`linux-musl`, as the two Linux packages would otherwise share a file name, and
glibc's stays `linux`, so every package named so far keeps its name.

## def layout
The tree sits at `package/` under its profile's directory, where `optzst create`
reads a package's program from. One home for every product (User): `bin/` holds
each product's binary, `mcp/` the MCP's own parts, its skills, and what the
products share sits at the top, `nu/`, `plugin/`, and `equip/`; `ssh/`,
grammar-ssh's own, is made when it has any. nushell's binary sits in `nu/bin/`,
apart from the products', so an install links every entry of `bin/` and no other
shell's `nu` is shadowed. Each binary finds the shared parts beside its `bin/`.
The binaries come from the target directory the build used (`target_dir`), each
with its target's executable suffix. The tree is emptied and rebuilt rather than
updated, so a file dropped from the release cannot linger in it. `plugin/` keeps
its plugins apart by kind: `core/` nushell's, `grammar/` the workspace's own;
`rig/`, for custom plugins, is the MCP's to read when one exists. `equip/` holds
each builtin's equip as its source holds it, the host's install taking its
`lib/` and `rig/`. `sys/` holds what a platform's own services take, the
cleanup's `sys/systemd/user/` in every Linux tree, glibc's and musl's alike,
since a musl build may run on a systemd host; an install links nothing from it.
On Unix, `chmod
u=rwX,go=rX` leaves directories and executables at 0755 and everything else at
0644, the modes the archive records; Windows keeps no such modes.

## def exe_suffix
Rust names a binary for its target: `.exe` on Windows, nothing elsewhere; the
layout names every binary it copies by it.

## def plugin_targets
A plugin is any workspace binary named `nu_plugin_*`, the prefix the MCP
registers a bundled plugin by, read from cargo's metadata, so a plugin crate
added under `crate/plugin/` reaches `plugin/grammar/` with no list to keep.
